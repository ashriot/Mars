# Repository Agent Guidance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the minimal root agent notes with concise, durable repository guidance and add a central documentation index.

**Architecture:** `AGENTS.md` is the safety and workflow contract that every agent reads first. `docs/README.md` is the expandable router for detailed or changing project knowledge, so product and UX decisions do not accumulate in the root instructions.

**Tech Stack:** Markdown, Godot 4.6.3, GUT 9.6.1, Git

## Global Constraints

- Preserve the unrelated cursor and test changes already present in the working tree.
- Keep gameplay behavior, UX preferences, balance decisions, and architecture research under `docs/`.
- Use short requirements and single-line documentation pointers.
- Every introduced link must resolve to an existing path.
- Automated tests must never touch ordinary local save data.

### Task 1: Add the Documentation Index

**Files:**
- Create: `docs/README.md`

**Interfaces:**
- Consumes: Existing documentation under `docs/testing/`, `docs/refactor.md`, `docs/superpowers/specs/`, and `docs/superpowers/plans/`.
- Produces: The stable documentation entry point referenced by root `AGENTS.md`.

- [ ] **Step 1: Create the documentation index**

Create `docs/README.md` with one-line links to testing instructions, each manual checklist, refactor research, validated designs, and implementation plans. State that designs and plans are historical implementation context that must be checked against current code. Define focused topic documents under `docs/` as the home for future UX, gameplay, architecture, progression, and content decisions, and require new topic documents to be linked from this index.

- [ ] **Step 2: Verify every index link**

Run:

```sh
for path in docs/testing/README.md docs/testing/controller-manual-checklist.md docs/testing/dungeon-manual-checklist.md docs/testing/starting-role-kit-checklist.md docs/refactor.md docs/superpowers/specs docs/superpowers/plans; do test -e "$path" || exit 1; done
```

Expected: exit status `0` with no output.

### Task 2: Replace the Root Agent Guidance

**Files:**
- Modify: `AGENTS.md`
- Reference: `docs/README.md`
- Reference: `docs/testing/README.md`

**Interfaces:**
- Consumes: The documentation entry point from Task 1 and the established Godot/GUT testing workflow.
- Produces: Durable repository-wide instructions for future coding agents.

- [ ] **Step 1: Write the root guidance**

Replace the current two bullets with concise sections covering:

- The local pre-alpha status, Godot 4.6.3 runtime, and major repository directories.
- One-line pointers to `docs/README.md` and `docs/testing/README.md`.
- Inspection, scope control, preservation of unrelated work, and the absence of speculative backward-compatibility work.
- Preservation of required `.uid` and `.import` sidecars, exclusion of `.godot/`, and lowercase snake_case naming for new paths where practical.
- Mandatory isolated test `HOME`, save-data isolation, risk-proportional verification, and manual UX checks.
- Evolving UX and product decisions under `docs/`, with no volatile detail duplicated in `AGENTS.md`.
- Superpowers for substantial efforts and the normal focused workflow for small changes.
- Handoff expectations and protection of unrelated files during staging or commits.
